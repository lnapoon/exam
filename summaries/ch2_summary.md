## 2. สรุปเนื้อหาโดยละเอียดครบทุกหน้าและทุกหัวข้อ

### บทนำ: องค์ประกอบของระบบเครือข่ายและเหตุผลของการแบ่งระดับชั้น (หน้า 1 / หน้า 19)
ในระบบเครือข่ายจะประกอบไปด้วยทั้ง **ฮาร์ดแวร์ (Hardware)** และ **ซอฟต์แวร์ (Software)** เพื่อทำหน้าที่ในการส่งข้อมูลจากต้นทางไปยังปลายทางได้อย่างถูกต้องและมีประสิทธิภาพ:
1. **ฮาร์ดแวร์ (Hardware)**: ทำหน้าที่ในการ**ประมวลผล** และ**นำสัญญาณทางไฟฟ้าต่าง ๆ** จากต้นทางไปยังปลายทาง
2. **ซอฟต์แวร์ (Software)**: เป็นส่วนสำคัญที่คอย**ควบคุมการทำงานของฮาร์ดแวร์** อีกทั้งยังเป็นส่วนที่**ติดต่อกับผู้ใช้ (User)** ด้วย

เนื่องจากระบบเครือข่ายมีกระบวนการทำงานที่ซับซ้อน ในการอธิบายการทำงานของระบบเครือข่ายจึงต้อง**แบ่งการทำงานออกเป็นระดับชั้นต่าง ๆ (Layered Architecture / Network Layer)** เพื่อลดความซับซ้อนและทำให้ง่ายต่อการทำความเข้าใจและการออกแบบระบบ

### 2.1 การทำงานแบบเป็นลำดับชั้น (Layered Tasks) (หน้า 1–2 / หน้า 19–20)

![รูปที่ 2.1 และ 2.3: อุปมาการส่งจดหมายทางไปรษณีย์ (Layered Tasks) & Peer-to-Peer และ Interface](/Users/monphrakan/.gemini/antigravity/brain/8c904e52-21d0-4450-974b-e2a98e0523c2/diagrams/ch2_layered_mail_peer.svg)
*แสดงลำดับขั้นการส่งจดหมาย 3 ชั้น และหลักการทำงานของ Peer-to-Peer Processes ผ่าน Interface ระหว่างเลเยอร์*

เพื่อให้เข้าใจแนวคิดการทำงานแบบเป็นลำดับชั้น ตำราได้ยกตัวอย่าง **ลำดับขั้นตอนของการส่งจดหมายทางไปรษณีย์ (รูปที่ 2.1)** ซึ่งประกอบด้วย **ผู้ส่ง (Sender)**, **ผู้รับ (Receiver)** และ **ผู้นำส่งจดหมาย (Carrier)** โดยแบ่งการทำงานออกเป็น **3 ระดับชั้น (3 Layers)** ได้แก่:
- **ชั้นบน (Higher Layers)**
- **ชั้นกลาง (Middle Layers)**
- **ชั้นล่าง (Lower Layers)**
- และมีสื่อกลางการขนส่งด้านล่างสุด (*The parcel is carried from the source to the destination*) เช่น ทางรถยนต์ รถไฟ เรือ หรือเครื่องบิน

#### ลำดับการทำงานฝั่งผู้ส่ง (Sender) — ทำงานจากชั้นบนลงชั้นล่าง (ขั้นที่ 3 → ขั้นที่ 2 → ขั้นที่ 1):
- **ขั้นที่ 3 (Higher Layer)**: ผู้ส่งจดหมายเขียนจดหมาย → นำจดหมายใส่ซอง → เขียนที่อยู่ของผู้ส่งและผู้รับ → นำจดหมายหย่อนลงในตู้รับจดหมาย (*The letter is written, put in an envelope, and dropped in mailbox.*)
- **ขั้นที่ 2 (Middle Layer)**: จดหมายถูกนำออกจากตู้รับจดหมายไปยังที่ทำการไปรษณีย์ต้นทาง (*The letter is carried from the mailbox to a post office.*)
- **ขั้นที่ 1 (Lower Layer)**: ที่ทำการไปรษณีย์ต้นทางทำการคัดแยกจดหมาย และส่งมอบให้ผู้นำส่งจดหมาย (Carrier) เพื่อนำจดหมายไปยังไปรษณีย์ปลายทาง (*The letter is delivered to a carrier by the post office.*)

#### การขนส่งจากต้นทางไปปลายทาง (Physical Transport):
- ผู้นำส่งจดหมายนำพัสดุ/จดหมายจากต้นทางไปยังปลายทาง โดยสามารถใช้ระบบขนส่งได้หลายแบบ เช่น รถยนต์ รถไฟ เรือ หรือเครื่องบิน

#### ลำดับการทำงานฝั่งผู้รับ (Receiver) — ทำงานจากชั้นล่างขึ้นชั้นบน (ขั้นที่ 1 → ขั้นที่ 2 → ขั้นที่ 3):
- **ขั้นที่ 1 (Lower Layer)**: ไปรษณีย์ปลายทางทำการรับจดหมายจากผู้นำส่งจดหมาย (*The letter is delivered from the carrier to the post office.*)
- **ขั้นที่ 2 (Middle Layer)**: จดหมายถูกนำมาจัดเรียง และนำส่งจากที่ทำการไปรษณีย์ปลายทางไปยังตู้จดหมายของผู้รับ (*The letter is carried from the post office to the mailbox.*)
- **ขั้นที่ 3 (Higher Layer)**: เมื่อผู้รับได้รับจดหมายแล้ว → หยิบจดหมาย เปิดซองจดหมาย → อ่านจดหมาย (*The letter is picked up, removed from the envelope, and read.*)

#### หลักการสำคัญที่ได้จากการทำงานแบบลำดับชั้น:
1. ในแต่ละชั้นของการทำงานจะมี**หน้าที่ที่แตกต่างกันออกไปอย่างชัดเจน**
2. **ที่ต้นทาง (Sender)**: จะต้องทำงานจาก **ระดับชั้นบนสุดไปยังระดับชั้นล่างสุด** (Top-down: 3 → 2 → 1)
3. **ที่ปลายทาง (Receiver)**: จะทำงานจาก **ระดับชั้นล่างสุดไปยังระดับชั้นบนสุด** (Bottom-up: 1 → 2 → 3)
4. **เงื่อนไขการทำงาน**: ในแต่ละระดับชั้น**จะต้องทำงานในชั้นของตนให้เสร็จก่อน** จึงจะสามารถส่งต่อไปทำงานในระดับชั้นถัดไปได้

### 2.2 แบบจำลองของอินเทอร์เน็ต (Internet Model / TCP/IP Protocol Suite) (หน้า 2–14 / หน้า 20–32)

#### 1) โครงสร้าง 5 เลเยอร์ของแบบจำลองอินเทอร์เน็ต (หน้า 2–3 / หน้า 20–21)
เนื่องจากอินเทอร์เน็ตเป็นเครือข่ายที่ใหญ่ที่สุดและมีผู้ใช้งานทั่วโลก การอธิบายแบบจำลองเครือข่ายจึงใช้ **แบบจำลองของอินเทอร์เน็ต (Internet Model)** เป็นหลัก หรือเรียกอีกชื่อหนึ่งที่รู้จักกันทั่วไปว่า **ชุดโพรโตคอลทีซีพี/ไอพี (TCP/IP protocol suite)** ซึ่งประกอบด้วยลำดับชั้นหรือ **เลเยอร์ (Layers)** ที่ซ้อนทับกันอยู่ทั้งหมด **5 เลเยอร์** เรียงจากล่างสุด (เลเยอร์ 1) ไปบนสุด (เลเยอร์ 5) ดังรูปที่ 2.2:

| ลำดับเลเยอร์ | ชื่อเลเยอร์ (ภาษาไทย) | ชื่อเลเยอร์ (ภาษาอังกฤษ) | หน่วยข้อมูล (PDU) | แอดเดรสที่ใช้ |
| :---: | :--- | :--- | :---: | :---: |
| **เลเยอร์ที่ 5** | แอพพลิเคชันเลเยอร์ | **Application layer** | Message (ข้อมูล/ข้อความ) | ชื่อบริการ / ข้อมูลเฉพาะแอป |
| **เลเยอร์ที่ 4** | ทรานสปอร์ตเลเยอร์ | **Transport layer** | Segment (เซ็กเมนต์) | **Port address** (พอร์ตแอดเดรส) |
| **เลเยอร์ที่ 3** | เน็ตเวิร์กเลเยอร์ | **Network layer** | Packet (แพ็กเก็ต) | **Logical address** (Network address / IP) |
| **เลเยอร์ที่ 2** | เดทาลิงค์เลเยอร์ | **Data link layer** | Frame (เฟรม) | **Physical address** (MAC address) |
| **เลเยอร์ที่ 1** | ฟิสิคัลเลเยอร์ | **Physical layer** | Bit (บิต 0, 1 / สัญญาณ) | - |

#### 2) หลักการทำงานของอุปกรณ์และการให้บริการระหว่างเลเยอร์ (หน้า 3 / หน้า 21)
- **อุปกรณ์ในเครือข่ายไม่จำเป็นต้องทำงานครบทั้ง 5 เลเยอร์**:
  - ขึ้นอยู่กับลักษณะการใช้งานของอุปกรณ์นั้น ๆ
  - เครื่องต้นทาง (Source/Device A) และเครื่องปลายทาง (Destination/Device B) จะทำงานครบทั้ง **5 เลเยอร์**
  - แต่อุปกรณ์ตัวกลาง (Intermediate nodes) ที่ข้อมูลวิ่งผ่านระหว่างทาง อาจจะทำงานแค่ **2 หรือ 3 เลเยอร์เท่านั้น** เช่น เราเตอร์ (Router) ที่เป็นโหนดตัวกลางในรูปที่ 2.3 และ 2.10 จะทำงานเพียง **3 เลเยอร์** (Physical, Data link, Network) หรือสวิตช์ (Switch) ทำงานเพียง **2 เลเยอร์** (Physical, Data link)
- **การให้บริการ (Services) ระหว่างเลเยอร์ในเครื่องเดียวกัน**:
  - แต่ละเลเยอร์มีความรับผิดชอบและหน้าที่แตกต่างกัน
  - **เลเยอร์ที่อยู่ต่ำกว่าจะทำหน้าที่ให้บริการ (Services) แก่เลเยอร์ถัดไปที่อยู่เหนือขึ้นไป** เช่น เลเยอร์ 1 ให้บริการแก่เลเยอร์ 2, เลเยอร์ 2 ให้บริการแก่เลเยอร์ 3, เลเยอร์ 3 ให้บริการแก่เลเยอร์ 4, และเลเยอร์ 4 ให้บริการแก่เลเยอร์ 5
- **การติดต่อสื่อสารระหว่าง 2 สถานี**:
  - แม้ข้อมูลจะถูกส่งไหลลง (ฝั่งส่ง) และไหลขึ้น (ฝั่งรับ) ตามเลเยอร์ต่าง ๆ แต่ในการติดต่อกันจริง ๆ ในเชิงตรรกะ จะเป็นการติดต่อกันระหว่าง **เลเยอร์เดียวกันเท่านั้น** (เช่น เลเยอร์ $x$ ของเครื่อง A จะติดต่อกับเลเยอร์ $x$ ของเครื่อง B)
  - เหตุผล: เพราะภายในเลเยอร์เดียวกันจะมี **โพรโตคอล (Protocol) เหมือนกัน** ทำให้สามารถพูดจาภาษาเดียวกันและเข้าใจกันได้ ส่วนเลเยอร์อื่น ๆ ก็จะมีโพรโตคอลที่แตกต่างกันออกไป

#### 3) เพียร์ทูเพียร์โพรเซส (Peer-to-Peer Processes) และอินเทอร์เฟซ (Interface) (หน้า 4 / หน้า 22)
- **เพียร์ทูเพียร์โพรเซส (Peer-to-Peer Processes)** (รูปที่ 2.3):
  - คือ กระบวนการสื่อสารข้อมูลกันระหว่างเลเยอร์ระดับเดียวกันของเครื่องส่งและเครื่องรับ โดยแต่ละเลเยอร์จะมีโพรโตคอลเป็นของตัวเอง แม้การส่งข้อมูลจริงจะต้องส่งผ่านเลเยอร์ต่าง ๆ ลงไปถึงสื่อกลาง แต่ในมุมมองของแต่ละเลเยอร์จะเสมือนว่าเลเยอร์เดียวกันนั้นติดต่อกันเองโดยตรง
  - จากรูปที่ 2.3:
    - **เลเยอร์ที่ 1, 2 และ 3 (Physical, Data link, Network)**: เป็นการติดต่อแบบโหนดต่อโหนด (ผ่าน Intermediate node) คือจาก Device A ↔ Intermediate node 1 ↔ Intermediate node 2 ↔ Device B
    - **เลเยอร์ที่ 4 และ 5 (Transport, Application)**: เป็นการติดต่อแบบ Peer-to-peer protocol ระหว่างปลายทางกับปลายทาง (Device A ↔ Device B) โดยไม่ถูกประมวลผลที่ Intermediate node
- **อินเทอร์เฟซ (Interface)**:
  - ในการส่งข้อมูลระหว่างเลเยอร์ที่อยู่ติดกันภายในเครื่องเดียวกัน จะต้องอาศัย **อินเทอร์เฟซ (Interface)** เป็นตัวกลางในการติดต่อ (ได้แก่ `5-4 interface`, `4-3 interface`, `3-2 interface`, `2-1 interface`)
  - **ความสำคัญของ Interface (ความเป็นอิสระของเลเยอร์)**: ถึงแม้ว่าแต่ละเลเยอร์จะมีการเปลี่ยนแปลงวิธีการทำงานภายในไปอย่างไรก็ตาม **ถ้าอินเทอร์เฟซไม่เปลี่ยนไป การเปลี่ยนแปลงนั้นก็จะไม่ส่งผลกระทบต่อการทำงานกันระหว่างเลเยอร์เลย** ทำให้ผู้ออกแบบระบบสามารถเปลี่ยนแปลงหรือเพิ่มเติมการทำงานในเลเยอร์ใด ๆ ได้โดยไม่ต้องไปแก้ไขการทำงานของเลเยอร์อื่น ๆ หรือกล่าวได้ว่า **แต่ละเลเยอร์เป็นอิสระจากกัน (Layer Independence)**

#### 4) การสื่อสารข้อมูลระหว่างเลเยอร์: การห่อหุ้มข้อมูล (Encapsulation) และการถอดข้อมูล (Decapsulation) (หน้า 5 / หน้า 23)

![รูปที่ 2.4: กระบวนการห่อหุ้มข้อมูล (Encapsulation) และการถอดข้อมูล (Decapsulation)](/Users/monphrakan/.gemini/antigravity/brain/8c904e52-21d0-4450-974b-e2a98e0523c2/diagrams/ch2_encapsulation.svg)
*แสดงการเพิ่ม Header (H5, H4, H3, H2) และการเพิ่ม Trailer (T2) เฉพาะที่ชั้น Data Link Layer เท่านั้น*

จากรูปที่ 2.4 การสื่อสารข้อมูลระหว่างเลเยอร์ภายใต้แบบจำลองอินเทอร์เน็ต:
- **ที่ฝั่งส่ง (ต้นทาง) — กระบวนการเพิ่ม Header/Trailer**:
  1. **เลเยอร์ที่ 5 (Application layer)**: ข้อมูลต้นฉบับ (`L5 data`) ถูกเพิ่มเฮดเดอร์ของเลเยอร์ 5 (`H5`) เข้าไปที่ส่วนหัว → `[L5 data | H5]` แล้วส่งผ่านอินเทอร์เฟซลงมายังเลเยอร์ 4
  2. **เลเยอร์ที่ 4 (Transport layer)**: มองก้อน `[L5 data | H5]` ทั้งหมดเป็นข้อมูลของเลเยอร์ 4 (`L4 data`) แล้วเพิ่มเฮดเดอร์ `H4` เข้าไปที่ส่วนหัว → `[L4 data | H4]` แล้วส่งลงมายังเลเยอร์ 3
  3. **เลเยอร์ที่ 3 (Network layer)**: มองก้อน `[L4 data | H4]` ทั้งหมดเป็นข้อมูลของเลเยอร์ 3 (`L3 data`) แล้วเพิ่มเฮดเดอร์ `H3` เข้าไปที่ส่วนหัว → `[L3 data | H3]` แล้วส่งลงมายังเลเยอร์ 2
  4. **เลเยอร์ที่ 2 (Data link layer)**: มองก้อน `[L3 data | H3]` ทั้งหมดเป็นข้อมูลของเลเยอร์ 2 (`L2 data`) และ **ในเลเยอร์ที่ 2 นี้จะมีการเพิ่มทั้งเฮดเดอร์ (`H2`) ที่ส่วนหัว และเทรเลอร์ (`T2` - Trailer) ที่ส่วนท้ายของเฟรมข้อมูล** → `[T2 | L2 data | H2]` แล้วส่งลงมายังเลเยอร์ 1 *(ข้อสังเกตสำคัญ: เลเยอร์ที่ 2 เป็นเลเยอร์เดียวที่มีการเพิ่มทั้ง Header และ Trailer)*
  5. **เลเยอร์ที่ 1 (Physical layer)**: ไม่มีการเพิ่ม Header หรือ Trailer แต่จะแปลงเฟรมข้อมูลทั้งหมดให้เป็นลำดับบิต (`010101010101101010000010000`) และเปลี่ยนไปเป็น **สัญญาณแม่เหล็กไฟฟ้า (Electromagnetic signals)** เพื่อส่งต่อไปยังสื่อกลาง (Transmission medium)
- **ที่ฝั่งรับ (ปลายทาง) — กระบวนการถอด Header/Trailer**:
  1. **เลเยอร์ที่ 1 (Physical layer)**: รับสัญญาณจากสื่อกลาง แล้วแปลงสัญญาณที่เข้ามานั้นให้อยู่ในรูปแบบของ **ข้อมูลดิจิตอล (Digital / บิต 0 และ 1)** แล้วส่งต่อให้เลเยอร์ที่ 2
  2. **เลเยอร์ที่ 2 (Data link layer)**: ทำการ **ถอดเฮดเดอร์ (`H2`) และเทรเลอร์ (`T2`) ออกไป** และทำงานตามโพรโตคอลในเลเยอร์ที่ 2 (เช่น ตรวจสอบความผิดพลาดจาก T2 และตรวจสอบ Physical address จาก H2) เมื่อเสร็จแล้วส่งข้อมูล (`L2 data`) ไปยังเลเยอร์ที่ 3
  3. **เลเยอร์ที่ 3, 4 และ 5**: ใช้หลักการเดียวกัน คือ ถอดเฮดเดอร์ของเลเยอร์ตนเอง (`H3`, `H4`, `H5`) ออกจากข้อมูล และทำงานตามโพรโตคอลของเลเยอร์นั้น ๆ
  4. หลังจากที่ **เลเยอร์ที่ 5** ถอดเฮดเดอร์ (`H5`) ออกแล้ว ก็จะได้ข้อมูล (`L5 data`) เหมือนกับที่ต้นทางได้ส่งมาให้ทุกประการ

### รายละเอียดหน้าที่ของแต่ละเลเยอร์ทั้ง 5 เลเยอร์

#### เลเยอร์ที่ 1: ฟิสิคัลเลเยอร์ (Physical Layer) (หน้า 5–6 / หน้า 23–24)
- **บทบาทหลัก**: เป็นเลเยอร์ระดับล่างสุดที่ทำหน้าที่ในการ **ส่งข้อมูลในระดับบิต (Bit)** ไปยังสื่อกลาง (Transmission medium) ที่ใช้ในการส่งข้อมูล
- **รูปที่ 2.5**: รับลำดับบิต `10101000000101111001` จาก Data link layer (From data link layer) → แปลงเป็นสัญญาณส่งผ่าน Transmission medium → Physical layer ปลายทางรับสัญญาณแปลงกลับเป็นบิต `10101000000101111001` ส่งให้ Data link layer (To data link layer)
- **หน้าที่หลักของฟิสิคัลเลเยอร์ (4 ข้อ)**:
  1. **กำหนดคุณสมบัติของอินเทอร์เฟซและสื่อ (Physical characteristics of interfaces and media)**: กำหนดคุณสมบัติ **ทางกล (Mechanical)** และ **ทางไฟฟ้า (Electrical)** ของอินเทอร์เฟซที่เชื่อมต่อระหว่างอุปกรณ์กับสื่อที่ใช้ในการส่งข้อมูล รวมถึงชนิดของสื่อนำสัญญาณ
  2. **การแทนบิตข้อมูลด้วยสัญญาณ (Representation of bits)**: สร้างข้อกำหนดในการแปลงข้อมูลระดับบิต (0 และ 1) ให้เป็นสัญญาณ (Signal) ต่าง ๆ เช่น **สัญญาณทางไฟฟ้า** หรือ **สัญญาณแสง** (กำหนดว่าจะเข้ารหัส/แปลงบิต 0 และ 1 เป็นสัญญาณอย่างไร)
  3. **กำหนดอัตราการส่งข้อมูล (Data rate / Transmission rate)**: กำหนดว่าในแต่ละวินาทีสามารถส่งข้อมูลได้จำนวนเท่าใด (จำนวนบิตต่อวินาที - bits per second) หรือระยะเวลาของแต่ละบิตนานเท่าใด
  4. **กำหนดความสอดคล้องกันของการรับส่งข้อมูลระดับบิต (Synchronization of bits)**: ทั้งฝ่ายรับและฝ่ายส่งจะต้องมี **สัญญาณนาฬิกา (Clock)** ที่สอดคล้องกัน (ซิงโครไนซ์กันในระดับบิต) เพื่อให้ฝ่ายรับอ่านจังหวะบิตได้ตรงกับที่ฝ่ายส่งส่งมา

#### เลเยอร์ที่ 2: เดทาลิงค์เลเยอร์ (Data Link Layer) (หน้า 6–8 / หน้า 24–26)

![รูปที่ 2.5, 2.6 และตัวอย่างที่ 1 (รูปที่ 2.8): การทำงาน Physical Layer, Data Link Layer และการส่งเฟรม MAC 10 → 87](/Users/monphrakan/.gemini/antigravity/brain/8c904e52-21d0-4450-974b-e2a98e0523c2/diagrams/ch2_physical_datalink_ex1.svg)
*แสดงการแปลงบิตในชั้น Physical, โครงสร้างเฟรม [T2|Data|H2] และตัวอย่างที่ 1 การส่งเฟรมภายในเครือข่ายเดียวกันจากโหนด 10 ไปโหนด 87*

- **บทบาทหลัก**:
  - รับข้อมูลระดับบิตมาจากฟิสิคัลเลเยอร์ ซึ่งอาจมีความผิดพลาด (Error) ที่เกิดจากการเดินทางผ่านสื่อกลาง ดังนั้นเดทาลิงค์เลเยอร์จึงต้องทำการตรวจสอบและแก้ไขข้อผิดพลาดของข้อมูล เพื่อทำให้ **เน็ตเวิร์กเลเยอร์ได้รับข้อมูลที่ปราศจากข้อผิดพลาด**
  - รับผิดชอบการส่งข้อมูลระหว่างโหนดที่เชื่อมต่ออยู่บนลิงก์หรือเครือข่ายเดียวกัน เรียกว่า **Hop-to-hop delivery** หรือ **Node-to-node delivery** (รูปที่ 2.7)
- **รูปที่ 2.6**: รับ Packet จาก Network layer มาจัดทำเป็น **เฟรม (Frame)** โดยเติม **Header (`H2`)** ที่ส่วนหัว และ **Trailer (`T2`)** ที่ส่วนท้าย → `[T2 | Data | H2]` ส่งให้ Physical layer
- **หน้าที่หลักของเดทาลิงค์เลเยอร์ (5 ข้อ)**:
  1. **การจัดแบ่งเฟรมข้อมูล (Framing)**: รับข้อมูล (Packet) มาจากเน็ตเวิร์กเลเยอร์ แล้วนำมาแบ่งออกเป็นหน่วยข้อมูลที่เรียกว่า **เฟรม (Frames)** เพื่อให้สะดวกและจัดการได้ง่ายในการจัดส่งข้อมูล
  2. **การกำหนดฟิสิคัลแอดเดรส (Physical addressing)**: เพิ่ม **ฟิสิคัลแอดเดรส (Physical address)** เข้าไปที่ **เฮดเดอร์ (`H2`)** ของเฟรม เพื่อระบุแอดเดรสของอุปกรณ์ต้นทาง (ผู้ส่ง) และอุปกรณ์ปลายทาง (ผู้รับ) ในเครือข่ายเดียวกัน (หรือโหนดถัดไปที่จะรับเฟรมนั้น)
  3. **ควบคุมอัตราการไหลของข้อมูล (Flow control)**: ในกรณีที่โหนดต้นทางและโหนดปลายทางมีความเร็วในการรับส่งข้อมูลไม่เท่ากัน (เช่น ฝ่ายรับประมวลผลช้ากว่าฝ่ายส่ง) จะทำให้ข้อมูลเกิดการสูญหายหรือล้นบัฟเฟอร์ได้ จึงต้องมีกลไกควบคุมอัตราการไหลของข้อมูล เพื่อให้การรับส่งของทั้งฝ่ายส่งและฝ่ายรับเกิดความสมดุลกัน
  4. **ควบคุมข้อผิดพลาดของข้อมูล (Error control)**: ในการรับส่งข้อมูลอาจเกิดเฟรมข้อมูลสูญหาย เสียหาย หรือมีการส่งเฟรมข้อมูลซ้ำ จึงต้องมีกลไกในการตรวจจับและส่งซ้ำเฟรมที่เสียหาย/สูญหาย รวมถึงป้องกันเฟรมซ้ำ ก่อนที่จะส่งให้กับเน็ตเวิร์กเลเยอร์ต่อไป โดย **การตรวจสอบความผิดพลาดของข้อมูลสามารถตรวจสอบได้จากบิตพิเศษในส่วนท้ายของเฟรม หรือ เทรเลอร์ (Trailer - `T2`)**
  5. **ควบคุมการใช้สื่อในการส่งข้อมูล (Access control)**: เมื่ออุปกรณ์หลายตัวเชื่อมต่อและใช้สื่อกลางในการส่งข้อมูลร่วมกัน (Shared link/media) มีโอกาสที่อุปกรณ์เหล่านั้นจะส่งข้อมูลออกมาพร้อม ๆ กัน ทำให้เกิด **การชนกันของข้อมูล (Collision)** จึงต้องมีกลไกควบคุมสิทธิ์ในการเข้าใช้สื่อกลางว่าอุปกรณ์ใดมีสิทธิ์ใช้สื่อในขณะนั้น
- **ตัวอย่างที่ 1 (รูปที่ 2.8 หน้า 8 / หน้า 26)**:
  - ในเครือข่ายเดียวกันที่มีโหนดฟิสิคัลแอดเดรส `10`, `28`, `53`, `65`, `87` เชื่อมต่ออยู่บนสายสื่อสัญญาณเดียวกัน
  - เมื่อโหนดที่มีฟิสิคัลแอดเดรสหมายเลข **10** ต้องการส่งเฟรมข้อมูลให้กับโหนดที่มีฟิสิคัลแอดเดรสหมายเลข **87**:
    - ใน **เฮดเดอร์ (Header)** ของเฟรมจะบรรจุฟิสิคัลแอดเดรสของผู้ส่ง (`Source address = 10`) และของผู้รับ (`Destination address = 87`)
    - ในส่วนท้ายของเฟรมหรือ **เทรเลอร์ (Trailer - `T2`)** จะบรรจุ **บิตพิเศษ (Extra bits)** เข้าไปด้วย เพื่อใช้ในการตรวจสอบความผิดพลาดของการส่งข้อมูล (Error detection)

#### เลเยอร์ที่ 3: เน็ตเวิร์กเลเยอร์ (Network Layer) (หน้า 9–11 / หน้า 27–29)

![รูปที่ 2.9–2.11 (ตัวอย่างที่ 2): การส่งข้อมูลข้ามเครือข่าย 3 Hop ผ่าน Router 1 และ Router 2](/Users/monphrakan/.gemini/antigravity/brain/8c904e52-21d0-4450-974b-e2a98e0523c2/diagrams/ch2_network_ex2.svg)
*แสดงการคงค่าของ Logical/IP Address (A → P) และการเปลี่ยนค่า Physical/MAC Address ในทุก Hop (10→20, 99→33, 66→95)*

- **บทบาทหลัก**:
  - รับผิดชอบในการส่งข้อมูล **จากเครื่องต้นทางไปยังเครื่องปลายทาง (Source-to-destination delivery หรือ End-to-end / Host-to-host delivery)** ให้ได้อย่างถูกต้อง **ถึงแม้ว่าการส่งข้อมูลนั้นจะเป็นการส่งข้ามเครือข่ายกัน (Internetworking)**
  - ความแตกต่างจาก Data link layer: เดทาลิงค์เลเยอร์เน้นการส่งข้อมูลภายในเครือข่ายเดียวกัน (Hop-to-hop / Node-to-node) แต่เน็ตเวิร์กเลเยอร์ดูแลการส่งข้อมูลข้ามหลายเครือข่ายตั้งแต่ต้นทางแรกสุดไปจนถึงปลายทางสุดท้าย (รูปที่ 2.10)
- **รูปที่ 2.9**: รับข้อมูล (Segment) จาก Transport layer มาเติม Header (`H3`) กลายเป็น **แพ็กเก็ต (Packet)** → `[Data | H3]` ส่งให้ Data link layer
- **หน้าที่หลักของเน็ตเวิร์กเลเยอร์ (2 ข้อ)**:
  1. **การกำหนดลอจิคัลแอดเดรส (Logical addressing)**: กำหนด **ลอจิคัลแอดเดรส (Logical address)** หรือเรียกอีกอย่างว่า **เน็ตเวิร์กแอดเดรส (Network address)** (เช่น IP Address) ของเครื่องต้นทางและเครื่องปลายทางใส่เข้าไปในส่วนหัวของแพ็กเก็ต (`H3`) เนื่องจากฟิสิคัลแอดเดรสในเดทาลิงค์เลเยอร์ใช้ระบุตัวตนได้เฉพาะภายในเครือข่ายเดียวกันเท่านั้น การส่งข้ามเครือข่ายจึงต้องใช้ลอจิคัลแอดเดรส
  2. **การหาเส้นทาง (Routing)**: ในการส่งข้อมูลข้ามเครือข่ายจะต้องส่งต่อกันเป็นทอด ๆ จากเครือข่ายหนึ่งไปยังอีกเครือข่ายหนึ่ง ผ่านอุปกรณ์เชื่อมโยงเครือข่ายที่เรียกว่า **เราเตอร์ (Router)** (หรือสวิตช์เลเยอร์ 3) และอาจเดินทางไปได้หลายเส้นทาง เน็ตเวิร์กเลเยอร์จึงต้องมีกลไกในการเลือกและหาเส้นทาง (Routing) เพื่อให้แพ็กเก็ตข้อมูลเดินทางไปยังปลายทางได้ถูกต้องและเร็วที่สุด
- **ตัวอย่างที่ 2 (รูปที่ 2.11 หน้า 10–11 / หน้า 28–29) — *จุดออกสอบสำคัญมาก!***:
  - เป็นการส่งข้อมูลข้ามเครือข่าย (ผ่านเครือข่าย Bus แรก → Router 1 → เครือข่าย Ring → Router 2 → เครือข่าย Bus สุดท้าย)
  - **ต้นทาง**: โหนดที่มี **เน็ตเวิร์กแอดเดรส (Logical address) = `A`**, **ฟิสิคัลแอดเดรส (Physical address) = `10`**
  - **ปลายทาง**: โหนดที่มี **เน็ตเวิร์กแอดเดรส (Logical address) = `P`**, **ฟิสิคัลแอดเดรส (Physical address) = `95`**
  - **อุปกรณ์เราเตอร์ (Router) ระหว่างทาง**:
    - **Router ตัวที่ 1**: พอร์ตที่เชื่อมกับ Bus แรกมีแอดเดรส `(Logical = F, Physical = 20)` และพอร์ตที่เชื่อมกับ Ring มีแอดเดรส `(Logical = T, Physical = 99)`
    - **Router ตัวที่ 2**: พอร์ตที่เชื่อมกับ Ring มีแอดเดรส `(Logical = N, Physical = 33)` และพอร์ตที่เชื่อมกับ Bus สุดท้ายมีแอดเดรส `(Logical = Z, Physical = 66)`
  - **การเปลี่ยนแปลงของแอดเดรสในเฟรมข้อมูลแต่ละทอด (Hop)**:
    1. **ทอดที่ 1 (จากโหนด A ไป Router 1 บนเครือข่าย Bus แรก)**:
       - Logical address: ต้นทาง = `A`, ปลายทาง = `P`
       - Physical address: ต้นทาง = `10` (โหนด A), ปลายทาง = `20` (ขาเข้า Router 1)
       - เฟรม: `[T2 | Data | A | P | 10 | 20]`
    2. **ทอดที่ 2 (จาก Router 1 ไป Router 2 บนเครือข่าย Ring)**:
       - Logical address: ต้นทาง = `A`, ปลายทาง = `P` *(ไม่เปลี่ยน)*
       - Physical address: ต้นทาง = `99` (ขาออก Router 1), ปลายทาง = `33` (ขาเข้า Router 2) *(เปลี่ยนใหม่)*
       - เฟรม: `[T2 | Data | A | P | 99 | 33]`
    3. **ทอดที่ 3 (จาก Router 2 ไปโหนด P บนเครือข่าย Bus สุดท้าย)**:
       - Logical address: ต้นทาง = `A`, ปลายทาง = `P` *(ไม่เปลี่ยน)*
       - Physical address: ต้นทาง = `66` (ขาออก Router 2), ปลายทาง = `95` (โหนด P) *(เปลี่ยนใหม่)*
       - เฟรม: `[T2 | Data | A | P | 66 | 95]`
  - **กฎเหล็กที่ต้องจำจากตัวอย่างที่ 2**:
    > ในการส่งข้อมูลข้ามเครือข่าย **ลอจิคัลแอดเดรส / เน็ตเวิร์กแอดเดรส (Logical/Network address) จะไม่มีการเปลี่ยนแปลงค่าเลยตลอดเส้นทาง** (ยังคงเป็นต้นทาง A และปลายทาง P เสมอ) **แต่ฟิสิคัลแอดเดรส (Physical address) จะเปลี่ยนแปลงไปเรื่อย ๆ ทุกครั้งที่ส่งผ่านเราเตอร์ (เปลี่ยนในทุก ๆ Hop)**

#### เลเยอร์ที่ 4: ทรานสปอร์ตเลเยอร์ (Transport Layer) (หน้า 11–13 / หน้า 29–31)

![รูปที่ 2.12, ตัวอย่างที่ 3 (รูปที่ 2.14) และรูปที่ 2.15: การแบ่งเซ็กเมนต์ พอร์ตแอดเดรส (j → k) และ Application Layer](/Users/monphrakan/.gemini/antigravity/brain/8c904e52-21d0-4450-974b-e2a98e0523c2/diagrams/ch2_transport_app_ex3.svg)
*แสดงการแบ่ง Data เป็น Data-1/Data-2 พร้อมใส่พอร์ต j, k และ IP A, P ไปประกอบรวมกลับที่ปลายทาง P รวมถึงบริการในชั้น Application*

- **บทบาทหลัก**:
  - เน็ตเวิร์กเลเยอร์ทำหน้าที่ส่งข้อมูลจากเครื่องต้นทางไปถึงเครื่องปลายทาง (Host-to-host / Source-to-destination delivery) ซึ่งจะเพียงพอก็ต่อเมื่อทั้งเครื่องต้นทางและเครื่องปลายทางมีโพรเซส (Process / โปรแกรมที่รันอยู่) เพียงโพรเซสเดียว
  - แต่ในความเป็นจริง คอมพิวเตอร์แต่ละเครื่องสามารถรัน **โพรเซส (Process) ในการรับส่งข้อมูลได้หลายโพรเซสพร้อมกัน** ดังนั้นทรานสปอร์ตเลเยอร์จึงทำหน้าที่รับผิดชอบใน **การรับส่งข้อมูลกันระหว่างโพรเซสต่อโพรเซส (Process-to-process delivery)** ของข้อความทั้งหมดให้ถูกต้องครบถ้วน (รูปที่ 2.13)
- **รูปที่ 2.12**: รับข้อมูล (Message) จาก Application layer มาแบ่งออกเป็น **เซ็กเมนต์ (Segments)** โดยแต่ละเซ็กเมนต์จะถูกเติม Header (`H4`) → `[Data | H4]` ส่งให้ Network layer และที่ฝั่งรับจะนำเซ็กเมนต์มารวมกลับเป็น Message ส่งให้ Application layer
- **หน้าที่หลักของทรานสปอร์ตเลเยอร์ (5 ข้อ)**:
  1. **การกำหนดพอร์ตแอดเดรส (Port addressing / Service-point addressing)**: เนื่องจากลอจิคัลแอดเดรสในเน็ตเวิร์กเลเยอร์ระบุได้เพียงว่าส่งไปที่ "เครื่องใด" แต่ไม่สามารถระบุได้ว่าต้องส่งให้ "โพรเซสใด" ภายในเครื่องนั้น ทรานสปอร์ตเลเยอร์จึงกำหนดหมายเลข **พอร์ต (Port) หรือ พอร์ตแอดเดรส (Port address)** ใส่ไว้ในเฮดเดอร์ (`H4`) เพื่อเป็นหมายเลขบ่งบอกถึงโพรเซสต้นทางและโพรเซสปลายทาง
  2. **การแบ่งข้อมูลเป็นเซ็กเมนต์และการประกอบรวมกลับ (Segmentation and reassembly)**: ข้อมูลที่มีขนาดใหญ่ซึ่งส่งลงมาจากแอพพลิเคชันเลเยอร์จะถูกแบ่งออกเป็นส่วนย่อย ๆ เรียกว่า **เซ็กเมนต์ (Segment)** โดยแต่ละเซ็กเมนต์จะมี **หมายเลขกำกับลำดับ (Sequence number)** บรรจุอยู่ในเฮดเดอร์ เมื่อโพรเซสฝ่ายรับได้รับเซ็กเมนต์เหล่านี้แล้ว ทรานสปอร์ตเลเยอร์จะใช้ **หมายเลขกำกับ (Sequence number)** ในการนำเซ็กเมนต์มารวมกัน (Reassembly) ให้เรียงลำดับถูกต้องเหมือนเดิม (รวมถึงตรวจสอบว่ามีแพ็กเก็ตใดสูญหายระหว่างทางหรือไม่) ก่อนส่งต่อไปยังแอพพลิเคชันเลเยอร์
  3. **การควบคุมการติดต่อกันระหว่างโพรเซส (Connection control)**: การติดต่อระหว่างโพรเซสสามารถทำได้ **2 แบบ** คือ:
     - **แบบไร้การเชื่อมต่อ (Connectionless)**: ไม่ต้องมีการสร้างการติดต่อกันระหว่างโพรเซสก่อน เมื่อต้องการรับส่งข้อมูลก็สามารถส่งแต่ละเซ็กเมนต์ออกไปเป็นอิสระได้ทันที
     - **แบบมีการเชื่อมต่อ (Connection-oriented)**: จะต้องมีการสร้างการติดต่อเชื่อมโยง (Connection establishment) ระหว่างโพรเซสต้นทางและปลายทางเสียก่อน จึงจะทำการรับส่งข้อมูลกันได้ และเมื่อส่งข้อมูลเสร็จแล้วก็จะทำการยุติการเชื่อมต่อ (Connection termination)
  4. **การควบคุมอัตราการไหลของข้อมูล (Flow control)**: ทำหน้าที่คล้ายกับเดทาลิงค์เลเยอร์ แต่แตกต่างกันตรงที่ในทรานสปอร์ตเลเยอร์เป็นการ **ควบคุมการไหลของข้อมูลระหว่างโพรเซสต้นทางถึงโพรเซสปลายทาง (Process-to-process / End-to-end)** ไม่ใช่แค่ระหว่างโหนดในลิงก์เดียว (Single link)
  5. **การควบคุมข้อผิดพลาดของข้อมูล (Error control)**: ควบคุมและตรวจสอบข้อผิดพลาดของข้อมูล **ระหว่างโพรเซสต้นทางกับโพรเซสปลายทาง (Process-to-process)** เพื่อให้มั่นใจว่าข้อมูลทั้งหมดไปถึงทรานสปอร์ตเลเยอร์ของปลายทางโดยสมบูรณ์ (ไร้การเสียหาย สูญหาย หรือซ้ำซ้อน) ซึ่งการแก้ไขข้อผิดพลาดมักทำโดยการส่งข้อมูลซ้ำ (Retransmission)
- **ตัวอย่างที่ 3 (รูปที่ 2.14 หน้า 13 / หน้า 31)**:
  - แสดงการส่งข้อมูล (`Data`) จาก Application layer ของเครื่อง `A` ไปยังเครื่อง `P`:
    1. **ที่ Application layer**: ส่ง `Data` ลงมา
    2. **ที่ Transport layer**: เนื่องจาก `Data` มีขนาดใหญ่ จึงแบ่งออกเป็น 2 ส่วนย่อย คือ `Data-1` และ `Data-2` พร้อมทั้งใส่ **หมายเลขพอร์ต (Port address)** เข้าไปที่เฮดเดอร์ ได้แก่:
       - **พอร์ต $j$**: หมายเลขโพรเซสของฝ่ายส่งข้อมูล (Source port)
       - **พอร์ต $k$**: หมายเลขโพรเซสของฝ่ายรับข้อมูล (Destination port)
       - ได้เป็น `[Data-1 | j | k]` และ `[Data-2 | j | k]`
    3. **ที่ Network layer**: ใส่ค่า **เน็ตเวิร์กแอดเดรส (`A` และ `P`)** เข้าไปที่เฮดเดอร์ของแต่ละแพ็กเก็ต:
       - ได้เป็น `[Data-1 | j | k | A | P]` และ `[Data-2 | j | k | A | P]`
    4. **ที่ Data link layer**: ใส่ **ฟิสิคัลแอดเดรส (`12`)** ที่เฮดเดอร์ และใส่ **เทรเลอร์ (`T2`)** ที่ส่วนท้าย:
       - ได้เป็น `[T2 | Data-1 | j | k | A | P | 12]` และ `[T2 | Data-2 | j | k | A | P | 12]`
    5. **การเดินทางและการรับที่ปลายทาง**: แพ็กเก็ตแต่ละตัวสามารถเดินทางผ่านอินเทอร์เน็ตไปในเส้นทางเดียวกันหรือเส้นทางที่แตกต่างกันก็ได้ เมื่อถึงเครื่องปลายทาง `P` จะทำย้อนกลับจากเลเยอร์ล่างขึ้นบน โดยแต่ละเลเยอร์ตรวจสอบและถอดเฮดเดอร์ของเลเยอร์ตนเองออก เมื่อถึงทรานสปอร์ตเลเยอร์ของเครื่อง `P` หลังจากถอดเฮดเดอร์ (`j, k`) ออกแล้ว จะนำ `Data-1` และ `Data-2` มารวมกันให้กลับเป็น `Data` เหมือนเดิม แล้วส่งขึ้นไปยังแอพพลิเคชันเลเยอร์

#### เลเยอร์ที่ 5: แอพพลิเคชันเลเยอร์ (Application Layer) (หน้า 13–14 / หน้า 31–32)
- **บทบาทหลัก**: เป็นเลเยอร์บนสุดที่เน้นในส่วนของ **การติดต่อกับผู้ใช้ (User interface)** และการจัดเตรียม **บริการ (Services) ต่าง ๆ ของเครือข่าย** ให้ผู้ใช้หรือโปรแกรมประยุกต์สามารถเข้าถึงทรัพยากรบนเครือข่ายได้
- **รูปที่ 2.15**: ผู้ใช้ (User) ใช้งานผ่านโพรโตคอลและบริการในแอพพลิเคชันเลเยอร์ เช่น **SMTP**, **Telnet**, **HTTP** โดยหน่วยข้อมูลคือ **Message** (`[Data | H5]`) ซึ่งส่งต่อให้กับ Transport layer
- **หน้าที่และบริการหลักของแอพพลิเคชันเลเยอร์ (4 ข้อ)**:
  1. **ให้บริการจดหมายอิเล็กทรอนิกส์ (Mail services)**: พื้นฐานสำหรับการรับ-ส่งอีเมล การส่งจดหมายต่อกันเป็นทอด (Forward) และการจัดเก็บอีเมล (เช่น โพรโตคอล SMTP)
  2. **การเข้าถึงและโอนย้ายไฟล์ข้อมูล (File transfer and access / FTAM)**: ช่วยให้ผู้ใช้สามารถเข้าถึง (Access) ดึง หรือจัดการไฟล์ในเครื่องคอมพิวเตอร์ระยะไกล และโอนย้ายไฟล์กันระหว่างเครื่องได้ (เช่น FTP)
  3. **การเข้าใช้งานเครื่องจากระยะไกล (Remote log-in / Network virtual terminal)**: ช่วยให้ผู้ใช้สามารถล็อกอินเข้าไปสั่งงานและใช้งานเครื่องคอมพิวเตอร์อื่น ๆ ที่อยู่ห่างไกลผ่านเครือข่ายได้เสมือนนั่งอยู่หน้าเครื่องนั้น (เช่น Telnet)
  4. **การใช้งานเวิลด์ไวด์เว็บ (Accessing the World Wide Web - WWW)**: การเข้าถึงข้อมูลเอกสารเว็บเพจและทรัพยากรบนอินเทอร์เน็ต (เช่น โพรโตคอล HTTP)

### 2.3 แบบจำลอง OSI (OSI Model) (หน้า 15 / หน้า 33)

![รูปที่ 2.2 และ 2.17: เปรียบเทียบแบบจำลอง Internet Model (5 เลเยอร์) กับ OSI Model (7 เลเยอร์)](/Users/monphrakan/.gemini/antigravity/brain/8c904e52-21d0-4450-974b-e2a98e0523c2/diagrams/ch2_osi_vs_tcpip.svg)
*แสดงความสัมพันธ์ระหว่าง Internet Model (5 ชั้น) และ OSI Model (7 ชั้น) พร้อมกลุ่ม User Support / Network Support และ PDU*

- **ชื่อเต็มและองค์กรผู้กำหนด**:
  - **OSI** ย่อมาจาก **Open Systems Interconnection** (ชื่อแบบจำลอง)
  - ถูกกำหนดและออกมาโดยองค์กร **ISO** ซึ่งย่อมาจาก **International Organization for Standardization** (องค์การระหว่างประเทศว่าด้วยการมาตรฐาน)
  - *(ข้อควรระวัง: อย่าสับสนระหว่าง ISO ซึ่งเป็นชื่อองค์กร กับ OSI ซึ่งเป็นชื่อแบบจำลองเครือข่าย)*
- **วัตถุประสงค์และสถานะของแบบจำลอง OSI**:
  - ออกแบบมาเพื่อเป็นมาตรฐานในการพัฒนาเครือข่ายการสื่อสารข้อมูลและคอมพิวเตอร์ให้ระบบเปิดต่าง ๆ สื่อสารกันได้ โดยแบ่งโครงสร้างเครือข่ายออกเป็นเลเยอร์และกำหนดการทำงานของแต่ละเลเยอร์
  - **แบบจำลอง OSI เป็นแบบจำลองที่เป็นเพียงทฤษฎี** เพื่อทำให้ง่ายต่อการเข้าใจและเห็นถึงการทำงานเป็นเลเยอร์ แต่ในทางปฏิบัติจริงในปัจจุบันจะใช้ **แบบจำลองของอินเทอร์เน็ต (TCP/IP 5 เลเยอร์)** เป็นหลัก
- **โครงสร้าง 7 เลเยอร์ของแบบจำลอง OSI (รูปที่ 2.17)**:
  เรียงจากเลเยอร์ล่างสุด (1) ไปบนสุด (7) ดังนี้:
  1. **Physical layer** (เลเยอร์ที่ 1)
  2. **Data link layer** (เลเยอร์ที่ 2)
  3. **Network layer** (เลเยอร์ที่ 3)
  4. **Transport layer** (เลเยอร์ที่ 4)
  5. **Session layer** (เลเยอร์ที่ 5) — *เพิ่มเข้ามาในแบบจำลอง OSI*
  6. **Presentation layer** (เลเยอร์ที่ 6) — *เพิ่มเข้ามาในแบบจำลอง OSI*
  7. **Application layer** (เลเยอร์ที่ 7)
- **หน้าที่ของ 2 เลเยอร์ที่เพิ่มเข้ามาในแบบจำลอง OSI**:
  1. **เซสชันเลเยอร์ (Session layer — เลเยอร์ที่ 5 ของ OSI)**:
     - เป็นเลเยอร์ที่ทำหน้าที่ในการ **สร้าง ดูแล และควบคุมเซสชัน (Session) กันระหว่างเครื่อง** เพื่อให้ผู้ใช้สามารถเชื่อมโยงกับเครื่องอื่น ๆ ได้ เช่น การล็อกอินเข้าใช้งานเครื่องระยะไกลในแต่ละครั้ง การควบคุมจังหวะการสนทนา (Dialog control) และการซิงโครไนซ์ข้อมูล
     - เมื่อมีการสร้างเซสชันกันแล้ว การรับส่งข้อมูลจะเรียกใช้บริการจากทรานสปอร์ตเลเยอร์
  2. **พรีเซนเทชันเลเยอร์ (Presentation layer — เลเยอร์ที่ 6 ของ OSI)**:
     - เป็นเลเยอร์ที่เกี่ยวข้องกับรูปแบบและโครงสร้างของข้อมูล โดยช่วย **แปลงรูปแบบของข้อมูล และแปลข้อมูล (Translation)** เพื่อให้การแลกเปลี่ยนข้อมูลระหว่างสองระบบที่มีการแทนข้อมูลต่างกันเป็นไปในรูปแบบเดียวกันที่เข้าใจกันได้
     - **หน้าที่สำคัญ 3 ประการของ Presentation layer**:
       1. **การแปลงรูปแบบและแปลข้อมูล (Translation)**
       2. **การเข้ารหัสข้อมูล และการถอดรหัสข้อมูล (Encryption and Decryption)**
       3. **การบีบอัดข้อมูล (Compression)**
- **ความสัมพันธ์ระหว่าง OSI Model (7 เลเยอร์) กับ Internet Model (5 เลเยอร์)**:
  - ในปัจจุบัน การทำงานของทั้ง **เซสชันเลเยอร์ (Session layer)** และ **พรีเซนเทชันเลเยอร์ (Presentation layer)** ได้ถูกนำมารวมและสร้างเป็นโพรโตคอลที่อยู่ในเลเยอร์ต่าง ๆ (โดยเฉพาะใน **Application layer**) ของแบบจำลองอินเทอร์เน็ตแล้ว เช่น การเข้ารหัส/ถอดรหัสข้อมูล หรือการบีบอัดข้อมูล

### สรุปท้ายบทและการจัดกลุ่มเลเยอร์ (หน้า 15–16 / หน้า 33–34)

![รูปที่ 2.18–2.19: หน้าที่ของ Session Layer และ Presentation Layer ในแบบจำลอง OSI 7 ชั้น](/Users/monphrakan/.gemini/antigravity/brain/8c904e52-21d0-4450-974b-e2a98e0523c2/diagrams/ch2_session_presentation_examples.svg)
*เจาะลึกหน้าที่เฉพาะของชั้นที่ 5 (Session: Dialog Control & Checkpoint) และชั้นที่ 6 (Presentation: Translation, Encryption, Compression)*

ในส่วนสรุปท้ายบท ได้แบ่งกลุ่มเลเยอร์ของแบบจำลองเครือข่ายออกเป็น **3 กลุ่มหลัก** ตามบทบาทหน้าที่ ดังนี้:
1. **กลุ่มเลเยอร์สนับสนุนการทำงานของเครือข่าย (Network support layers)**:
   - ได้แก่ **ฟิสิคัลเลเยอร์ (Physical layer)**, **เดทาลิงค์เลเยอร์ (Data link layer)** และ **เน็ตเวิร์กเลเยอร์ (Network layer)** (เลเยอร์ 1, 2, 3)
   - เน้นไปในส่วนของการทำงานของเครือข่ายทางกายภาพและการเคลื่อนย้ายข้อมูลจากอุปกรณ์หนึ่งไปยังอีกอุปกรณ์หนึ่ง (เช่น คุณสมบัติทางไฟฟ้า การเชื่อมต่อทางกายภาพ การกำหนดแอดเดรสระดับลิงก์และเครือข่าย การหาเส้นทาง และการตรวจสอบความน่าเชื่อถือของการส่งสัญญาณ)
2. **กลุ่มเลเยอร์สนับสนุนการทำงานที่เกี่ยวข้องกับผู้ใช้ (User support layer)**:
   - ได้แก่ **แอพพลิเคชันเลเยอร์ (Application layer)** (เลเยอร์ 5 ในแบบจำลองอินเทอร์เน็ต หรือรวม Session, Presentation, Application ในแบบจำลอง OSI)
   - เน้นไปในส่วนของการให้บริการและทำงานร่วมกับซอฟต์แวร์ของผู้ใช้โดยตรง
3. **เลเยอร์ตัวกลางที่เชื่อมโยงสองกลุ่มเข้าด้วยกัน (Linking layer)**:
   - ได้แก่ **ทรานสปอร์ตเลเยอร์ (Transport layer)** (เลเยอร์ 4)
   - ทำหน้าที่เป็น **ส่วนเชื่อมโยงระหว่างการทำงานของเครือข่าย (Network support layers) กับการทำงานที่เกี่ยวข้องกับผู้ใช้ (User support layer)** โดยทำให้มั่นใจว่าสิ่งที่ Network support layers ส่งมาถึงเครื่องปลายทางนั้น จะถูกจัดส่งต่อไปยังโพรเซสของผู้ใช้ในระดับ User support layer ได้อย่างถูกต้องและนำไปใช้งานได้ทันที

### เฉลยคำถามทบทวนและค้นคว้าท้ายบท (หน้า 16 / หน้า 34)

1. **จงอธิบายความแตกต่างระหว่างการส่งข้อมูลของเน็ตเวิร์กเลเยอร์ กับทรานสปอร์ตเลเยอร์**
   - **ตอบ**: **เน็ตเวิร์กเลเยอร์ (Network layer)** รับผิดชอบในการส่งข้อมูลระดับแพ็กเก็ตจาก **เครื่องต้นทางไปยังเครื่องปลายทาง (Source-to-destination หรือ Host-to-host delivery)** ข้ามเครือข่ายโดยใช้ลอจิคัลแอดเดรส (Logical/Network address) โดยไม่ได้สนใจว่าภายในเครื่องนั้นมีกี่โพรเซส ในขณะที่ **ทรานสปอร์ตเลเยอร์ (Transport layer)** รับผิดชอบในการส่งข้อมูลจาก **โพรเซสหนึ่งไปยังอีกโพรเซสหนึ่ง (Process-to-process delivery)** โดยใช้พอร์ตแอดเดรส (Port address) เพื่อระบุโพรเซสที่กำลังทำงานอยู่ภายในเครื่องต้นทางและเครื่องปลายทาง พร้อมทั้งดูแลการแบ่งเซ็กเมนต์ การประกอบกลับ และการควบคุมความผิดพลาดระหว่างโพรเซส

2. **จงอธิบายเพียร์ทูเพียร์โพรเซส (peer-to-peer process) ว่าเป็นอย่างไร**
   - **ตอบ**: คือกระบวนการสื่อสารข้อมูลกันระหว่างเลเยอร์ระดับเดียวกันของเครื่องต้นทางและเครื่องปลายทาง (หรือระหว่างโหนด) โดยในแต่ละเลเยอร์จะมีโพรโตคอล (Protocol) เฉพาะของเลเยอร์ตนเอง ถึงแม้ว่าในทางกายภาพข้อมูลจะต้องถูกส่งไหลลงผ่านเลเยอร์ต่าง ๆ ของฝั่งส่ง ไปยังสื่อกลาง แล้วไหลขึ้นผ่านเลเยอร์ต่าง ๆ ของฝั่งรับ แต่ในเชิงตรรกะแล้ว เสมือนกับว่าเลเยอร์เดียวกันของทั้งสองฝั่งกำลังติดต่อสื่อสารกันโดยตรงด้วยภาษา (โพรโตคอล) เดียวกัน

3. **เฮดเดอร์ (header) และเทรเลอร์ (trailer) มีไว้เพื่ออะไร มีวิธีเพิ่มเข้าและถอดออกจากข้อมูลได้อย่างไร**
   - **ตอบ**:
     - **มีไว้เพื่อ**: บรรจุข้อมูลควบคุม (Control information) ที่จำเป็นต่อการทำงานของโพรโตคอลในแต่ละเลเยอร์ เช่น เฮดเดอร์ใช้เก็บแอดเดรสต้นทาง/ปลายทาง (Physical address ใน H2, Logical address ใน H3, Port address ใน H4) และหมายเลขกำกับลำดับ (Sequence number) ส่วนเทรเลอร์ (Trailer - `T2` ซึ่งมีเฉพาะใน Data link layer) ใช้บรรจุบิตพิเศษ (Extra bits) สำหรับตรวจสอบความผิดพลาดของเฟรมข้อมูล (Error detection)
     - **วิธีเพิ่มเข้าและถอดออก**: ที่ **ฝั่งส่ง** เมื่อข้อมูลถูกส่งจากเลเยอร์บนลงมายังเลเยอร์ล่างผ่านอินเทอร์เฟซ แต่ละเลเยอร์ (5, 4, 3, 2) จะเพิ่ม **เฮดเดอร์** เข้าไปที่ส่วนหัวของข้อมูล (และเลเยอร์ 2 จะเพิ่ม **เทรเลอร์** เข้าไปที่ส่วนท้ายด้วย) เรียกว่ากระบวนการ Encapsulation ส่วนที่ **ฝั่งรับ** เมื่อข้อมูลถูกส่งจากเลเยอร์ล่างขึ้นไปยังเลเยอร์บน แต่ละเลเยอร์จะอ่านตรวจสอบแล้ว **ถอดเฮดเดอร์ (และเทรเลอร์ในเลเยอร์ 2)** ของเลเยอร์ตนเองออก ก่อนส่งเฉพาะส่วนข้อมูลต่อไปยังเลเยอร์ที่อยู่เหนือขึ้นไป เรียกว่ากระบวนการ Decapsulation

4. **จงบอกความแตกต่างระหว่างพอร์ตแอดเดรส (port address) ลอจิคัลแอดเดรส (logical address) และฟิสิคัลแอดเดรส (physical address)**
   - **ตอบ**:
     - **ฟิสิคัลแอดเดรส (Physical address)**: ทำงานใน **Data link layer (เลเยอร์ 2)** ใช้ระบุตัวตนของโหนดหรือการ์ดเครือข่าย **ภายในเครือข่ายเดียวกัน (Local network / Hop-to-hop)** และ **จะเปลี่ยนค่าไปเรื่อย ๆ ทุกครั้งที่เฟรมถูกส่งข้ามเครือข่ายผ่านเราเตอร์**
     - **ลอจิคัลแอดเดรส (Logical address / Network address)**: ทำงานใน **Network layer (เลเยอร์ 3)** ใช้ระบุตัวตนของเครื่องต้นทางและเครื่องปลายทางใน **การส่งข้อมูลข้ามเครือข่าย (Source-to-destination / Host-to-host)** และ **จะไม่เปลี่ยนแปลงค่าเลยตลอดการเดินทางจากต้นทางถึงปลายทาง**
     - **พอร์ตแอดเดรส (Port address)**: ทำงานใน **Transport layer (เลเยอร์ 4)** ใช้ระบุ **โพรเซส (Process) หรือโปรแกรมประยุกต์** ที่กำลังทำงานอยู่ภายในเครื่องต้นทางและเครื่องปลายทาง (**Process-to-process delivery**)

5. **จงหาว่ามีบริการ (service) อะไรบ้างที่อยู่ในแอพพลิเคชันเลเยอร์ของแบบจำลองอินเทอร์เน็ต**
   - **ตอบ**: มีบริการหลัก 4 ประการตามที่ระบุในบทเรียน ได้แก่:
     1. บริการจดหมายอิเล็กทรอนิกส์ (Mail services เช่น การรับ-ส่ง และการ Forward อีเมล)
     2. การเข้าถึงและโอนย้ายไฟล์ข้อมูล (File transfer and access เช่น การเข้าถึงไฟล์ระยะไกลและการโอนย้ายไฟล์ระหว่างเครื่อง)
     3. การเข้าใช้งานเครื่องจากระยะไกล (Remote log-in เช่น การล็อกอินเข้าไปใช้งานเครื่องอื่นผ่านเครือข่าย)
     4. การใช้งานเวิลด์ไวด์เว็บ (Accessing the World Wide Web - WWW)

6. **จงบอกว่าการทำงานต่าง ๆ ต่อไปนี้ควรจะต้องมีอยู่ในเลเยอร์ไหน**
   - การตัดสินใจในการเลือกเส้นทางของการเดินทางของข้อมูล (Routing) → **เน็ตเวิร์กเลเยอร์ (Network layer - เลเยอร์ 3)**
   - การควบคุมอัตราการไหลของข้อมูล (Flow control) → **เดทาลิงค์เลเยอร์ (Data link layer - เลเยอร์ 2)** (ระดับโหนดต่อโหนด) และ **ทรานสปอร์ตเลเยอร์ (Transport layer - เลเยอร์ 4)** (ระดับโพรเซสต่อโพรเซส)
   - เป็นส่วนอินเทอร์เฟซกับฮาร์ดแวร์และสื่อนำสัญญาณ → **ฟิสิคัลเลเยอร์ (Physical layer - เลเยอร์ 1)**
   - ทำแพ็กเก็ตสวิตช์ชิง (Packet switching) / ส่งแพ็กเก็ตข้ามเครือข่าย → **เน็ตเวิร์กเลเยอร์ (Network layer - เลเยอร์ 3)**
   - ทำให้ผู้ใช้ (User) สามารถเข้ามาใช้งานเครือข่ายได้ → **แอพพลิเคชันเลเยอร์ (Application layer - เลเยอร์ 5 ใน Internet Model / เลเยอร์ 7 ใน OSI)**
   - การรวบรวมแพ็กเก็ต (เซ็กเมนต์) ต่าง ๆ เข้ามาไว้ด้วยกันให้เหมือนเดิม (Reassembly) → **ทรานสปอร์ตเลเยอร์ (Transport layer - เลเยอร์ 4)**
   - ตรวจสอบความถูกต้องของข้อมูลและแก้ไขข้อมูลที่ผิดพลาด (Error control) → **เดทาลิงค์เลเยอร์ (Data link layer - เลเยอร์ 2)** และ **ทรานสปอร์ตเลเยอร์ (Transport layer - เลเยอร์ 4)**

| **1. Physical** | ส่งระดับบิตผ่านสื่อกลาง (Bit-by-bit over medium) | ไม่มี | Bit / Signal | - |
| **2. Data link** | **Hop-to-hop delivery** (หรือ **Node-to-node delivery**) | **Physical address** (ใส่ใน `H2`) | **Frame** (มีทั้ง `H2` และ `T2`) | **เปลี่ยนค่าเสมอ** ในทุก ๆ ทอด (ทุกครั้งที่ผ่าน Router) |
| **3. Network** | **Source-to-destination delivery** (หรือ **End-to-end / Host-to-host delivery**) | **Logical address** (หรือ **Network address** ใส่ใน `H3`) | **Packet** (มี `H3`) | **ไม่เปลี่ยนแปลงค่าเลย** ตลอดเส้นทางจากต้นทางถึงปลายทาง |
| **4. Transport** | **Process-to-process delivery** | **Port address** (ใส่ใน `H4`) | **Segment** (มี `H4`) | **ไม่เปลี่ยนแปลงค่า** (ระบุโพรเซส $j$ ของผู้ส่ง และโพรเซส $k$ ของผู้รับ) |
| **5. Application** | ติดต่อผู้ใช้และให้บริการเครือข่าย (User access to network resources) | ชื่อเฉพาะของแอปพลิเคชัน (เช่น อีเมล, URL) | **Message** (มี `H5`) | - |

### จุดเน้นที่ 2: ความแตกต่างสำคัญที่มักหลอกในข้อสอบ
1. **เลเยอร์เดียวที่มี Trailer (`T2`)**:
   - คือ **Data link layer (เลเยอร์ที่ 2)** เท่านั้น! เลเยอร์อื่น ๆ (3, 4, 5) มีเฉพาะ Header (`H3`, `H4`, `H5`) ส่วน Physical layer (เลเยอร์ 1) ไม่มีการเติมทั้ง Header และ Trailer
   - **หน้าที่ของ Trailer (`T2`)**: บรรจุบิตพิเศษ (Extra bits) เพื่อใช้ใน **การตรวจสอบความผิดพลาดของข้อมูล (Error control / Error detection)**
2. **ISO vs OSI**:
   - **ISO** (*International Organization for Standardization*) = **ชื่อองค์กร**ผู้กำหนดมาตรฐาน
   - **OSI** (*Open Systems Interconnection*) = **ชื่อแบบจำลองเครือข่าย 7 เลเยอร์** (ซึ่งเป็นแบบจำลองเชิงทฤษฎี)
3. **เปรียบเทียบ Internet Model (5 เลเยอร์) กับ OSI Model (7 เลเยอร์)**:
   - OSI Model มีเพิ่มขึ้นมา **2 เลเยอร์** คือ **เลเยอร์ที่ 5 Session layer** (สร้างเซสชันเชื่อมโยงระหว่างเครื่อง) และ **เลเยอร์ที่ 6 Presentation layer** (แปลงรูปแบบข้อมูล แปลภาษา เข้ารหัส/ถอดรหัส และบีบอัดข้อมูล)
   - ใน Internet Model (5 เลเยอร์) หน้าที่ของ Session layer และ Presentation layer ถูกรวมไว้ใน **Application layer**
4. **การจัดกลุ่มเลเยอร์ 3 กลุ่ม (หน้า 15–16)**:
   - **Network support layers (เลเยอร์ 1, 2, 3)**: Physical + Data link + Network
   - **User support layer (เลเยอร์ 5 ของ Internet / 5, 6, 7 ของ OSI)**: Application (+ Session, Presentation)
   - **ตัวเชื่อมโยง (Linking layer - เลเยอร์ 4)**: **Transport layer** เป็นตัวเชื่อมระหว่าง Network support layers กับ User support layer
5. **เลเยอร์ที่มีทั้ง Flow Control และ Error Control**:
   - มีอยู่ **2 เลเยอร์** คือ **Data link layer (เลเยอร์ 2)** และ **Transport layer (เลเยอร์ 4)**
   - ต่างกันที่ขอบเขต: ใน **Data link layer** ทำในระดับ **โหนดต่อโหนด (Node-to-node / Hop-to-hop)** บนลิงก์เดียว แต่ใน **Transport layer** ทำในระดับ **โพรเซสต้นทางถึงโพรเซสปลายทาง (Process-to-process / End-to-end)** ตลอดทั้งการเชื่อมต่อ
6. **จำนวนเลเยอร์ที่อุปกรณ์ทำงาน**:
   - เครื่องต้นทางและเครื่องปลายทาง (End systems / Devices A & B) ทำงานครบ **5 เลเยอร์**
   - โหนดตัวกลาง เช่น **เราเตอร์ (Router / Intermediate node)** ทำงานเพียง **3 เลเยอร์ล่าง** (Physical, Data link, Network) ไม่ได้ขึ้นไปถึง Transport และ Application
7. **Sequence Number อยู่ในเลเยอร์ใด**:
   - หมายเลขกำกับลำดับ (**Sequence number**) ถูกใส่ใน **Transport layer (เลเยอร์ 4)** เมื่อแบ่งข้อมูลเป็น **Segment** เพื่อให้ฝั่งรับนำมารวมกลับ (Reassembly) ได้ถูกต้องตามลำดับเดิม
8. **Connectionless vs Connection-oriented**:
   - เป็นกลไก **Connection control** ใน **Transport layer (เลเยอร์ 4)**
   - **Connectionless**: รับส่งข้อมูลได้ทันทีโดยไม่ต้องสร้างการเชื่อมต่อล่วงหน้า
   - **Connection-oriented**: ต้องสร้างการติดต่อ (Connection) ระหว่างโพรเซสก่อนส่งข้อมูลเสมอ
